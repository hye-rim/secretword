# 숨은 단어 🔎

단어를 숨기고 **뜻이 가까운 단어**로 힌트를 내서 맞히는 단어 추리 게임. 컴퓨터와 번갈아 출제하거나, **방 코드로 친구와 온라인 대전**을 한다. [작은 오락실](https://github.com/hye-rim/smallgame)의 게임 중 하나.

- 구조: `public/`(`index.html` + `logic.js` + `game.js` + `data/`) + `server.js`(정적 파일 + WebSocket, `ws`). 컴퓨터 대전은 브라우저에서만 돌고, 온라인 대전은 서버가 판정한다.
- 실행: `npm install` 후 `npm start` (기본 포트 3029), 시험은 `npm test`.

- **규칙** (방송 「히든 워드」를 1:1 로):
  - 처음에 각자 숨길 단어 후보 **5개**를 받는다. 1라운드에 그중 하나, 2라운드에 남은 4개 중 하나를 숨긴다.
  - 출제자는 숨긴 단어와 관련된 힌트를 하나씩 낸다. 힌트마다 **유사도(%)**가 공개되고, **95% 이상**인 힌트가 나와야 힌트 단계가 끝난다(그 전엔 계속 내야 함). 숨긴 단어 자체, 글자가 겹치는 단어는 힌트로 못 쓴다.
  - 맞히는 쪽은 답을 **하나** 쓴다. 답은 **맞음·틀림만** 알려 주고 유사도는 보여 주지 않는다. 틀리면 🧩 **피스**를 써서 하나 더 쓸 수 있다(한 판에 2개).
  - 맞히면 맞힌 쪽 **1점**, 차례 끝. 못 맞히면 출제자가 단계 점수(**1차 1점, 2차 2점, 3차 3점**)를 얻고 다음 힌트 단계로, 3차까지. **2라운드는 모든 점수 2배**. 라운드마다 컴퓨터(온라인은 무작위로 정한 쪽)가 먼저 출제.
  - 방송과 다르게 정한 것: 피스는 한 판에 2개씩 주고, 95% 이상 단어(숨긴 단어와 가장 가까운 10개)를 다 써 버린 단계는 다음 힌트로 끝낸다.
- **유사도 눈금**: 단어 벡터 코사인을 숨긴 단어마다 맞춘 %로 바꾼다. 가장 가까운 단어 99.99%, **10번째로 가까운 단어가 정확히 95%**, 그 아래는 코사인 −0.1 이 0% 가 되게 곧게 줄인다(100위 ≈ 70%, 1000위 ≈ 50%).
- **컴퓨터**: 출제는 단계마다 95% 미만 힌트 몇 개를 먼저 내고(쉬움 1개·가까운 것, 보통 1~3개, 어려움 2~4개·다른 정답 후보에도 가까운 헷갈리는 것) 마지막에 95% 이상 힌트. 맞히기는 힌트 유사도와 가장 잘 맞는 단어를 힌트용 단어 1만여 개 전체에서 찾되(정답 후보 목록은 모름) 유사도를 흐릿하게 읽는다(표준편차 쉬움 30, 보통 18, 어려움 9 %p). 보통 출제 기준 컴퓨터끼리 40차례: 맞히는 쪽 쉬움 15번 못 맞힘, 보통 8번, 어려움 1번. 피스는 쉬움 3차에만, 보통 2차부터, 어려움은 바로 쓴다.
- **온라인 대전**(커넥트4와 같은 틀): 빠른 대전, 방 만들기(4글자 코드·초대 링크), 재접속 토큰(새로고침해도 30초 안에 같은 자리로), 한 판 더(먼저 출제하는 쪽이 바뀜), 나가면 상대 승리, 없는 방 코드를 여러 번 대면 1분 막기, `maxPayload` 4KB.
  - **숨긴 단어는 서버만 안다**: 맞히는 쪽 브라우저에는 차례가 끝날 때까지 정답도, 출제자의 후보 5개도 보내지 않는다. 유사도 계산, 힌트 규칙 검사, 💡 추천도 서버가 한다(규칙 코드 `public/logic.js` 를 서버와 브라우저가 같이 씀).
  - **제한 시간**: 숨길 단어 고르기 30초(넘기면 첫 후보), 한 단계 힌트 3분(넘기면 서버가 95% 이상 힌트를 내서 끝냄), 한 단계 답 60초(넘기면 못 맞힌 것으로), 차례 결과 12초(둘 다 다음을 누르면 바로). 시험에서는 `SECRET_MS`·`HINT_MS`·`GUESS_MS`·`NEXT_MS` 로 줄인다.
  - 온라인 판은 전적에 넣지 않는다.
- **저장**: 난이도별 전적 `secretwordRec`, 로비 표시용 총 승수 `secretwordWins`, `secretwordMuted`.

## 단어 자료 (`public/data/`)

- `words.txt`: 한 줄에 `단어\t표시` (2 = 정답 후보, 1 = 컴퓨터 힌트·맞히기 후보, 0 = 사람이 써도 되는 단어). 19,122개.
- `vecs.bin`: 단어마다 100개의 int8 (약 1.9MB).
- `anchors.bin`: 단어마다 가장 가까운 단어·10번째 단어의 코사인(Float32 2개, 150KB). 유사도 눈금의 기준이고, 컴퓨터가 후보마다 힌트 유사도를 예상할 때 쓴다. `tools/anchors.js` 로 만든다(약 12초). 브라우저(컴퓨터 대전)는 `fetch` 로 상대경로에서 읽고, 서버(온라인 대전)는 시작할 때 읽는다.
- 출처: [fastText 한국어 Common Crawl 벡터](https://fasttext.cc/docs/en/crawl-vectors.html) `cc.ko.300.vec` (Facebook, **CC BY-SA 3.0**). 이 자료를 줄이고 압축한 `public/data/` 도 같은 라이선스를 따른다.
- 만드는 법(`tools/`, 원본 1.2GB 는 저장소에 넣지 않음):
  1. `nouns.js`: 빈도순 앞쪽 60만 어휘에서 조사 붙은 꼴(사과를·사과가·사과에…)이 3개 이상 있는 한글 단어를 명사 후보로 뽑는다.
  2. `build.js`: 조사가 붙은 꼴·한 글자·기능어를 빼고 정답 후보를 더한다. `vecs.js`: 그 단어들의 벡터를 꺼내 정규화.
  3. `pca.js`: 평균을 빼고 주성분 100개로 줄여 int8 로 양자화. `pack.js`: `public/data/` 로 묶는다(뜻이 여러 갈래인 한 글자 단어는 정답에서 뺌).
- 웹 크롤 문장으로 배운 벡터라 사람 감각과 다른 순위가 나오기도 한다(예: 공항-비행기 253위, 원본 300차원에서도 602위).

시험은 `node --test`. `test/logic.test.js`: 유사도 눈금(1위 99.99, 10위 95.00), 후보 5개·2라운드 남은 4개, 힌트 거절과 95% 이상이 나올 때까지 계속, 답은 맞음·틀림만(유사도 없음)·피스·넘기기·단계 점수, 1점·1+2+3점·2라운드 2배, 95% 이상 단어가 바닥난 단계, 연습 1라운드, 컴퓨터 힌트가 매 단계 95% 이상으로 끝나는지, 컴퓨터 답, 난이도 순서. `test/server.test.js`: 잘못된 주소·점 파일·큰 메시지, 출제자만 후보를 받고 맞히는 쪽은 정답을 못 받는지, 95% 이상까지 힌트·거절, 답은 맞음·틀림만·피스·넘기기·점수·출제자 교대, 아무도 안 하면 제한 시간으로 끝까지(출제자 1+2+3점), 나가기·한 판 더, 방 코드, 재접속, 방 코드 무차별 대입 막기.
