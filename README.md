# 숨은 단어 🔎

단어를 숨기고 **뜻이 가까운 단어**로 힌트를 내서 맞히는 단어 추리 게임. 컴퓨터와 번갈아 출제하거나, **방 코드로 친구와 온라인 대전**을 한다. [작은 오락실](https://github.com/hye-rim/smallgame)의 게임 중 하나.

- 구조: `public/`(`index.html` + `logic.js` + `game.js` + `data/`) + `server.js`(정적 파일 + WebSocket, `ws`). 컴퓨터 대전은 브라우저에서만 돌고, 온라인 대전은 서버가 판정한다.
- 실행: `npm install` 후 `npm start` (기본 포트 3029), 시험은 `npm test`.

- **유사도**: 두 단어가 얼마나 가까운지를 AI 단어 벡터의 코사인 유사도(×100)로 보여 준다. **순위**는 숨긴 단어와 가까운 순서(1위 = 가장 가까운 단어, 사전 1.9만 단어 중).
- **한 차례**: 출제자가 정답 후보 252개 중 하나를 숨긴다(사람은 5개 중 고르고 🔄 로 다시 뽑기). 한 단계에 힌트 **2개** → 맞히는 쪽이 답 **3번**. 힌트와 답 모두 유사도·순위가 공개된다.
- **힌트 규칙**: 단계별로 순위 안에 들어야 한다(1단계 300위, 2단계 100위, 3단계 30위 안). 1~3위는 너무 가까워서 금지, 숨긴 단어와 글자가 겹치는 단어도 금지. 💡 는 쓸 수 있는 힌트 하나를 채워 준다.
- **점수**: 1·2·3단계에 맞히면 3·2·1점, 끝까지 못 맞히면 출제자 2점. 2라운드(컴퓨터 출제 → 내 출제 × 2), **2라운드는 점수 2배**. 연습(튜토리얼)은 1라운드.
- **컴퓨터**: 출제는 쉬움=가까운 힌트, 보통=순위 범위 전체, 어려움=다른 정답 후보에도 가까운 헷갈리는 힌트. 맞히기는 힌트·지난 답의 유사도와 가장 잘 맞는 단어를 힌트용 단어 1만여 개 전체에서 찾는다(정답 후보 목록만 보면 너무 잘 맞혀서 사람과 같은 조건으로 했다). 유사도를 흐릿하게 읽는 정도로 세기를 나눈다(표준편차 쉬움 0.2, 보통 0.13, 어려움 0.08). 보통 출제 기준 컴퓨터끼리 60차례: 어려움은 거의 다 1~2단계에 맞히고, 쉬움은 40% 정도 못 맞힌다.
- **온라인 대전**(커넥트4와 같은 틀): 빠른 대전, 방 만들기(4글자 코드·초대 링크), 재접속 토큰(새로고침해도 30초 안에 같은 자리로), 한 판 더(먼저 출제하는 쪽이 바뀜), 나가면 상대 승리, 없는 방 코드를 여러 번 대면 1분 막기, `maxPayload` 4KB.
  - **숨긴 단어는 서버만 안다**: 맞히는 쪽 브라우저에는 차례가 끝날 때까지 정답도, 출제자의 후보 5개도 보내지 않는다. 유사도·순위 계산, 힌트 규칙 검사, 💡 추천도 서버가 한다(규칙 코드 `public/logic.js` 를 서버와 브라우저가 같이 씀).
  - **제한 시간**: 숨길 단어 고르기 30초(넘기면 첫 후보), 한 단계 힌트 90초(넘기면 남은 힌트를 서버가 규칙에 맞게 채움), 한 단계 답 60초(넘기면 남은 답은 버림), 차례 결과 12초(둘 다 다음을 누르면 바로). 시험에서는 `SECRET_MS`·`HINT_MS`·`GUESS_MS`·`NEXT_MS` 로 줄인다.
  - 다시 뽑기는 차례마다 3번. 온라인 판은 전적에 넣지 않는다.
- **저장**: 난이도별 전적 `secretwordRec`, 로비 표시용 총 승수 `secretwordWins`, `secretwordMuted`.

## 단어 자료 (`public/data/`)

- `words.txt`: 한 줄에 `단어\t표시` (2 = 정답 후보, 1 = 컴퓨터 힌트·맞히기 후보, 0 = 사람이 써도 되는 단어). 19,122개.
- `vecs.bin`: 단어마다 100개의 int8 (약 1.9MB). 브라우저(컴퓨터 대전)는 `fetch` 로 상대경로에서 읽고, 서버(온라인 대전)는 시작할 때 읽는다.
- 출처: [fastText 한국어 Common Crawl 벡터](https://fasttext.cc/docs/en/crawl-vectors.html) `cc.ko.300.vec` (Facebook, **CC BY-SA 3.0**). 이 자료를 줄이고 압축한 `public/data/` 도 같은 라이선스를 따른다.
- 만드는 법(`tools/`, 원본 1.2GB 는 저장소에 넣지 않음):
  1. `nouns.js`: 빈도순 앞쪽 60만 어휘에서 조사 붙은 꼴(사과를·사과가·사과에…)이 3개 이상 있는 한글 단어를 명사 후보로 뽑는다.
  2. `build.js`: 조사가 붙은 꼴·한 글자·기능어를 빼고 정답 후보를 더한다. `vecs.js`: 그 단어들의 벡터를 꺼내 정규화.
  3. `pca.js`: 평균을 빼고 주성분 100개로 줄여 int8 로 양자화. `pack.js`: `public/data/` 로 묶는다(뜻이 여러 갈래인 한 글자 단어는 정답에서 뺌).
- 웹 크롤 문장으로 배운 벡터라 사람 감각과 다른 순위가 나오기도 한다(예: 공항-비행기 253위, 원본 300차원에서도 602위).

시험은 `node --test`. `test/server.test.js`: 잘못된 주소·점 파일·큰 메시지, 빠른 대전에서 출제자만 후보를 받고 맞히는 쪽은 정답을 못 받는지, 힌트 거절(정답·모르는 단어, 맞히는 쪽의 힌트), 세 번 틀리면 2단계·정답 점수·둘 다 다음이면 출제자 교대, 아무도 안 하면 제한 시간으로 끝까지 진행(힌트 자동 채움, 출제자 2점), 나가기(나간 사람에게는 결과를 안 보냄)·한 판 더, 방 코드·세 번째 손님 거절, 재접속, 방 코드 무차별 대입 막기. `test/logic.test.js`: 자료 읽기와 순위, 출제 단어 조건, 힌트 거절 이유(모르는 단어·정답·글자 겹침·너무 가까움·너무 멂·이미 나옴), 단계 진행, 점수(단계별·출제자·2라운드 2배), 연습 1라운드, 컴퓨터 힌트가 항상 규칙 안인지, 컴퓨터 답이 겹치지 않는지, 난이도 순서(고정 난수).
